# Проверка визуализации и сравнение с pip

Дата проверки: 14 ноября 2026 г. Python 3.14, macOS arm64, pip 25.2,
D2 0.9.0. Данные PyPI и результаты зависят от даты и версии пакетов.

Команды из корня репозитория:

```sh
for p in requests idna certifi; do
  sh run.sh "$p" --repository https://pypi.org > "$p.d2"
  d2 "$p.d2" "$p.svg"
done
python3 -m venv /tmp/deps-comparison
/tmp/deps-comparison/bin/pip install requests
/tmp/deps-comparison/bin/pip inspect > /tmp/pip-inspect.json
```

Все три файла D2 успешно преобразованы в SVG. Текстовые результаты сохранены
рядом: [requests](requests.d2), [idna](idna.d2), [certifi](certifi.d2).
У `requests` получены четыре ребра: к `charset-normalizer`, `idna`, `urllib3`
и `certifi`. Графы `idna` и `certifi` в этой проверке состоят из одной
вершины. SVG не добавлены в репозиторий: их можно построить приведённой
командой. Для отображения напрямую: `sh run.sh requests --repository
https://pypi.org --image`.

В отдельном окружении pip установил `requests` 2.34.2, `charset-normalizer`
3.5.2, `idna` 3.20, `urllib3` 2.8.0 и `certifi` 2026.10.23. Вывод
`pip inspect` содержит те же четыре основных зависимости requests; для idna
и certifi установленных обязательных зависимостей нет. Таким образом, для
этого примера имена и рёбра совпадают. Сам pip не предоставляет штатной
команды рисования графа: сравнение выполнено с метаданными `pip inspect` и
составом установленного окружения, а не с графическим выводом pip.

В общем случае результаты могут расходиться: pip разрешает ограничения
версий и проверяет маркеры среды и extras. Эта программа получает метаданные
последней версии каждого имени, не разрешает версии и не вычисляет маркеры
платформы; записи с `extra == ...` исключаются целиком. Поэтому она не
является заменой резолвера pip.

Тестовый граф проверяется командами из README. В нём A → B → D → A образует
цикл, C также зависит от D, а E изолирован. Для корня A запрос обратных
зависимостей D возвращает A, B, C; для E результат пуст. Поиск ограничен
графом, достижимым из заданного корня.
